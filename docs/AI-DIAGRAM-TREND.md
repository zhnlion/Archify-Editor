> 归档日：2026-10-16。  
> 本文归档行业演进判断，并用它重排 [`SYMBOL-COMPARE.md`](./SYMBOL-COMPARE.md) 里尚未做的条目。

## 1. 洞察

权威已经从画布上的形状，挪到一份可校验的图。模型负责写出拓扑，人负责改几何和语义，渲染器负责交付。

四段是叠加上去的：

| 阶段 | 大约时间 | 图存在哪里 | 代表 | 卡住的地方 |
|------|----------|------------|------|------------|
| 人摆形状 | 2023 前 | 绝对坐标加样式 | 主流流程图编辑器 | 模型写不好又长又脆的坐标文件 |
| 文本即图 | 2023–2024 | Mermaid、PlantUML、D2 | 助手写进 Markdown，平台渲染 | 布局归求解器，位置留不住 |
| 生成后可改 | 2024–2026 | 先文本或 XML，再进画布 | draw.io Generate；商业图示 Agent；Eraser 再提示 | 再生成会重排，人改过的位置被丢掉 |
| 助手进回路 | 2025–2026 | 仓库里的图，或带校验的 JSON | 编程助手写 Mermaid；Eraser MCP；从代码或 Terraform 抽架构 | 图种会漂，草稿会被当成现状 |

2026 年的分界线是谁决定节点放哪：

| 布局归谁 | 对模型 | 对人 | 本编辑器里的角色 |
|----------|--------|------|------------------|
| 求解器（Mermaid、D2、Graphviz） | 只写拓扑 | 改了也会被重排 | 导入草稿，几何改由编辑器接管 |
| 绝对坐标（draw.io XML） | 费 token，容易算错 | 能精修 | 导出子集，不当模型的母语 |
| 相对约束 | 比坐标好写，语法还在变 | 中等 | 先观察，不引入第三套语法 |
| 类型化 IR，坐标可空 | 写节点和边 | `pos` / `size` 以编辑器为准 | 现有 flowchart / architecture JSON |

转换器常见的错也已经稳定：图种漂移（架构被画成思维导图）、截图丢细线和交叉、把注释里的愿望画成已有组件、Mermaid 再生成整图重排。draw.io 自己的 Mermaid 容器写明：重新生成会丢掉几何修改。

验收就一句：对话里说「把判断改成两个出口」时，改的是边和文案，人拖过的位置、拐点、锚点和色标还在。

对本编辑器，AI 再添一条进入现有 IR 的路。模型不写 Archify HTML。人改完仍走 Bridge，finalize 剥 `meta.editor`。

## 2. 排优先级用的三件事

一条 [`SYMBOL-COMPARE.md`](./SYMBOL-COMPARE.md) 里的缺口，只有帮助下面三件事才往上排：

1. **模型写得动**：类型、节点、边、文案、色标名称。坐标可以空着。
2. **人留得住**：已有 `pos`、`via`、锚点、泳道尺寸、色标定义，在再次导入时保留。
3. **交付不被污染**：架构自由填色不进 Archify HTML；图种只有 flowchart 和 architecture。

只让画布更像通用绘图软件、却不参与这三步的，放到后面。日常流程图该有的插入和编辑（20 形、多选、对齐、吸附、边柄、拐点、泳道）已经落地，不再排期。

## 3. 重点完善（已列为 P0，按这个顺序）

| 顺序 | 需求 | 条目 | 对照出处 | 为什么抬上来 | 验收 |
|------|------|------|----------|--------------|------|
| 1 | F-22 | 空坐标的有限布局，加上再次导入时合并几何 | E-F20 | 模型交得出拓扑，交不出稳定坐标。导入要能摆开；人改过的位置不能被下一次生成冲掉 | 无 `pos` 的节点得到分层或网格位置。带 `pos` / `via` / `fromSide` / `toSide` 的节点和边保持原样，只更新文案和增删的边 |
| 2 | F-23 | 命名色标，以及由色标生成的图例 | SYMBOL-COMPARE §7 | 模型写得出「待审核」「外部依赖」这种名字，写不好一串颜色。改一处定义，引用它的框一起变。数据在 `meta.editor.colorTags`，finalize 仍剥掉 | 流程图色标留在编辑 JSON。架构图编辑态可变色，导出 HTML 仍按组件类型 |
| 3 | F-24 | 判断出边默认「是 / 否」 | E-F18 | 流程图草稿几乎都有分支。两条文案比再加一个形状有用 | 第一条默认「是」，第二条默认「否」；已有文案不覆盖 |
| 4 | F-09 / F-18 | draw.io 子集进出 | E-F21 | 生成后可改的那一端，很多人仍停在 draw.io。子集是迁移口，不是形状库竞赛 | 矩形、菱形、边、文字、填色能进出。厂商图标丢掉并提示。夹具进 TEST-MATRIX |
| 5 | F-25 | 架构边拐点，以及 boundary 成员 | SYMBOL-COMPARE 架构编辑 | 架构草稿分组（「这三块在同一边界里」）和绕障，要人在画布上收得住 | 架构边可拖 `via`。boundary 的 `wraps` 可增删。`curve` 仍在 finalize 时去掉 |

色标的字段维持 SYMBOL-COMPARE 的建议：`id`、`label`、`fill`、`stroke`、`text`；节点记 `tagId`，应用时写入现有 `style`。`ArchifyComponent.tag` 继续当角标文案，不拿来当色标。

第 1 项还没做转换器界面也可以先做：它同时服务现有的 Mermaid / workflow 导入。转换器以后只是这条 IR 的另一个入口，图种校验和有损清单沿用现在的导入。

## 4. 放低

这些在 SYMBOL-COMPARE 里是「未做」或「部分」，行业演示里也常见。它们不决定模型能不能交一张可改的图，排在 §3 之后。

| 一堆 | SYMBOL-COMPARE 里的条目 | 放到后面的原因 |
|------|-------------------------|----------------|
| 上色配套 | 格式刷（E-F16）、整图主题、泳道标题色和带身分开、边标签徽章底色 | 语义上色用色标。格式刷是色标落地之后的效率，不代替色标 |
| 手感细节 | Shift 等比（E-F17）、边标签拖偏移（E-F19）、旋转、组合 / 解组、置顶 / 置底、锁定 | 人修几何时用得上，不阻塞导入和再生成 |
| 自由形状 | 椭圆、三角形、自由圆角矩形、自由六边形、独立文本框、图片、大括号、自由直线、垂直泳道、画布标题形状 | 通用绘图。流程和架构的文案在节点上，泳道保持横带 |
| ANSI 冷门形 | 多文档、磁鼓、磁带、卡片、穿孔纸带、内部存储、波浪底存储、跨页连接符、或门、汇总、排序、提取、合并、对照 | Mermaid 和自然语言草稿几乎不产生这些形。现有 20 形够用 |
| 记号体系 | BPMN 任务族、网关、事件、消息流、关联、池套道；UML 活动；状态与终态；UML 类 / 组件 / 部署；ER | E-F22 维持「真有一份流程需要时再加 1～3 个形」，不追平约 270 个 BPMN。判断菱形和子过程继续承担日常分支和子流程 |
| 架构图标 | 云轮廓、防火墙图标、队列图标、人物、服务器、负载均衡、路由器、交换机 | 七类语义框加类型色已经是架构图的形状。图标库整库维持不做 |
| 其它编辑 | 形状按名称搜索、画布编辑 cards、跨层依赖规则、手工输入和手工操作拆成两个形 | 符号只有二十来个，搜索收益小。cards 已经随 HTML 保留。跨层规则等分层成为每天在用的模式再做 |

## 5. 维持不做

SYMBOL-COMPARE「范围外」和「整库」行维持 DESIGN §3.6：

- AWS、Azure、GCP、Kubernetes、Cisco、阿里云、IBM、SAP、Citrix，以及通用网络图标、商业工具「网络与电脑」类库
- 时序图、思维导图、组织架构、楼层、电路、P&ID、移动端线框、剪贴画、手绘、实时协作
- 渐变、阴影、手绘风格
- 把自由填色写进 Archify HTML
- 把 draw.io 的 style 字符串存进 IR
- 用形状搜索 tag 充当颜色
- 相对约束语法。可以关注，不在本仓加第三套图语言
